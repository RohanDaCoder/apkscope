# AGENTS.md

Context for AI coding agents working in this repository. Humans: see [CONTRIBUTING.md](CONTRIBUTING.md)
for the full contribution workflow; this file is the short, operational version.

## Project overview

apkscope is an Android APK decompiler, xref engine and MCP server written in Rust: one executable,
no JVM. It renders DEX as typed Java, searches code/strings/resources/URLs/secrets, follows
references and call graphs, edits Smali and resources, rebuilds and re-signs APKs, and ships a
native viewer (egui) and an MCP server for AI agents. Everything is written from scratch — it is
not a JADX fork or a wrapper.

Workspace layout:

| Path | What it is |
|---|---|
| `src/` | The `apkscope` binary: decompiler pipeline (`ir.rs`, `java.rs`, `opt.rs`, `deobf.rs`), stateless queries (`quick.rs`), reference index (`index.rs`), opened-APK session (`session.rs`), RE helpers (`re.rs`), search cache (`cache.rs`), export/import (`export.rs`, `imports.rs`), live Frida (`live.rs`, `gui/live_ui.rs`), IL2CPP (`il2cpp.rs`), ELF (`elf.rs`), the MCP server (`mcp.rs`), the viewer (`gui.rs`, behind the `gui` feature), CLI parsing (`opt.rs`, `main.rs`) |
| `core/` | The `apkscope-core` library crate: the editing half. APK/ZIP reader (`apk.rs`), DEX table reader/writer (`dex.rs`), Dalvik decoder (`bytecode.rs`), Smali round trip (`smali/`), `resources.arsc` as a model (`table/`), values XML (`values.rs`, `res.rs`), resources as files (`resources.rs`), binary XML (`axml.rs`, `xml/`, `markup.rs`), rebuild (`rebuild.rs`), signing (`apksign.rs`, `sign.rs`), the error type (`error.rs`) |
| `bench/` | Benchmark and regression harnesses; `regress.py` + `baseline.json` guard decompiler quality |
| `packaging/linux/` | `.deb` and AppImage packaging |
| `scripts/` | `install.sh` / `install.ps1` (+ uninstalls): download release binaries, verify SHA-256 |
| `docs/` | `RELEASE_NOTES.md` and benchmark SVGs (generated by `bench/charts.py` — never edit by hand) |
| `assets/` | Logo, icons, Windows resource script |
| `.github/workflows/` | `ci.yml` (quality gate + 3-OS build matrix) and `release.yml` (v* tags) |

## Build and test commands

```bash
cargo build --release                          # viewer + CLI + MCP server (default features)
cargo build --release --no-default-features    # CLI + MCP server only (the macOS / musl build)
cargo test --release --no-default-features     # what CI runs on every OS
cargo fmt --all -- --check                     # formatting — CI fails on drift
cargo clippy --release --no-default-features -- -D warnings
cargo check --release                          # compiles the gui tree too (default features)
```

`--no-default-features` drops the viewer; plain cargo commands build and test both crates
(the workspace `default-members` are `.` and `core`). Tests are inline `#[cfg(test)] mod tests`
blocks at the end of each file — there is no `tests/` directory; add tests in the file they cover.
Run one module's tests with `cargo test --release --no-default-features dex::`.

Before declaring any code task done, run the fmt, clippy, check (both feature sets) and test lines
above and make them all pass. Documentation-only changes need none of them.

## Conventions

- **Conventional Commits** with the area as scope: `feat(core): …`, `fix(smali): …`, `docs: …`,
  `perf(index): …`. Types in use: `feat`, `fix`, `docs`, `refactor`, `perf`, `test`, `build`, `ci`,
  `chore`.
- **Branches:** always branch off `upstream/main` (`git checkout -b feat/x upstream/main`); never
  work on or open PRs from `main` — a branch is shared by every PR that uses it, so a second PR
  from `main` would silently add its changes to the first. One branch per change.
- **rustfmt defaults**, no custom config. Code comments are lowercase and explain *why*, not what.
- **Every module starts with a `//!` doc comment** (one or two lines, see `core/src/lib.rs`).
- **In `core/`, every fallible function returns `apkscope_core::Error`** (the `thiserror` enum in
  `core/src/error.rs`), never `String`; malformed APKs are normal input, so parse code must error,
  not panic. The core's promise is *byte-for-byte*: writing back what was read changes nothing —
  the tests assert it.
- **Dependencies:** "one small binary, no JVM" is a product promise; do not add runtime
  dependencies without a strong case, and check both feature sets compile.
- **Keep `README.md` honest:** benchmarks quote only measured numbers from `bench/`; if you change
  what the tool does, update the README, the honest-limits section and `docs/RELEASE_NOTES.md`
  together.

## Decompiler and benchmark workflow

- Quality counters (methods failed, gotos, warnings) are baselined in `bench/baseline.json`;
  `python bench/regress.py <apkscope.exe> <app.apk>...` fails when they regress. Run it on
  decompiler changes; `--update` re-records the baseline (mention it in the PR).
- `bench/results.json` holds measured numbers; `bench/charts.py` regenerates `docs/bench-*.svg`.
  Never hand-edit those SVGs, and never put unmeasured numbers in `results.json`.
- The wall-time harnesses (`asc.ps1`, `open.ps1`, `search.ps1`, `measure.ps1`) are PowerShell and
  expect Windows paths for the compared tools; `bench/mcp.py` runs on any OS.

## MCP server specifics

- The server lives in `src/mcp.rs`: JSON-RPC 2.0 over stdio, one message per line, implemented
  with no MCP SDK. Stateless tools exec the CLI in a fresh process (identical behavior to the
  command line, many APKs at once); `cache: true` tools go to a warm per-APK worker that keeps the
  session (reference index, disk code cache, deobfuscation) loaded.
- Replies page with `limit` / `offset` and cap at 60,000 characters; `app_only` hides androidx,
  Play services and ad SDKs. Keep those semantics when changing tool replies.
- A warm worker unused for 10 minutes exits and frees its memory — don't hold per-APK state
  without that timeout.

## Ethics and safety

apkscope is a reverse-engineering / pentesting tool. Analyze only apps you own or are authorized to
analyze. Never commit copyrighted APKs, decompiled output of copyrighted apps, or real secrets into
this repository; findings in issues and PRs should be trimmed to the relevant lines. Don't put
exploit-grade details for vulnerabilities in apkscope itself into public issues.
